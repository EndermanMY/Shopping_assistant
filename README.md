# 购物小助手

运行在 Windows 上的本地购物控制台，目前支持京东。电脑负责预约、购物车准备、定时下单与订单核验，同一局域网内的手机可配置任务、查看进度和停止任务。适用于个人单账号、单件购买，同一账号串行执行任务，付款由用户手动完成。

[下载正式版](https://github.com/EndermanMY/Shopping_assistant/releases/latest) · [版本记录](https://github.com/EndermanMY/Shopping_assistant/releases) · [问题反馈](https://github.com/EndermanMY/Shopping_assistant/issues)

## 功能

- 解析京东商品链接、分享文案或 SKU，检查预约状态并准备购物车。
- 按北京时间场次执行，支持毫秒提前量和秒级持续时间。
- 提前准备结算，提供页面提交与可选 API 提交；默认使用页面提交。
- 展示实时日志、失败截图、候选订单号与核验结果，支持停止、删除和受保护的重置。
- 使用独立浏览器保存登录会话，提供访问码认证和局域网手机控制台。

当前正式版为 **v0.2.0**。API 已整合到 `main`，通过每个任务的“调用 API 提交订单”开关启用，不再单独维护 API 分支。详细变更见 [v0.2.0 发布记录](docs/RELEASE-v0.2.0.md)。

## 快速开始

### Windows 便携版（推荐）

1. 从 [最新正式版](https://github.com/EndermanMY/Shopping_assistant/releases/latest) 下载 Windows x64 ZIP 和同名 `.sha256` 校验文件。
2. 完整解压，保留包内目录结构，双击 `start.bat`。无需另装 Python、Node.js 或本机 Chrome。
3. 打开终端显示的地址，默认 `http://127.0.0.1:18765/`，输入终端显示的控制台访问码。
4. 点击“打开京东登录”，在程序自带的独立浏览器中登录。

启动窗口需保持运行，电脑需保持开机、联网且不休眠。发布包不预置账号、登录会话或任务。可使用 PowerShell 的 `Get-FileHash <ZIP路径> -Algorithm SHA256` 核对下载文件。

升级前停止旧服务并备份本人运行数据，保留旧包以便回退。迁移时保留新版浏览器运行文件；不要用旧包整个覆盖新包。具体步骤见 [升级说明](docs/RELEASE-v0.2.0.md#使用与迁移) 及包内 `READ-ME-FIRST.md`。升级和重启不会自动启用任务。

### 从源码运行

需要 Windows、Python 3.12+、Node.js 22.12+ 或 24+。在项目根目录运行：

```powershell
.\install.ps1
.\start.ps1
```

也可双击 `install.bat` 和 `start.bat`。多个 Python 环境时，可显式指定：

```powershell
.\install.ps1 -PythonPath 'C:\Path\To\Python312\python.exe'
```

安装脚本使用官方 PyPI/npm 源，Python 环境位于 `.venv/`，浏览器运行文件位于 `data/browsers/`。依赖由 `requirements.lock.txt`、`frontend/package-lock.json` 和 `browser-runtime.lock.json` 固定。

## 创建与执行任务

1. 解析商品，确认精确 SKU、版本、规格和数量。当前仅支持单件购买，不自动替换规格。
2. 设置开抢时间、提前量和持续时间；普通模式还需填写含运费的最高应付金额及收货地址核对关键字。
3. 按需选择提交方式和核对模式，保存后检查配置，再手动“启用”。保存不会自动开始购买。
4. 助手检查或办理预约，将商品加入购物车并等待，到点执行结算与提交。
5. 查看订单核验结果；确认成功后，自行在京东完成付款。

“检查网页准备”只读取预约资格、购物车状态和订单列表，不会预约、勾选或下单。京东显示“已设置开抢提醒”时，提醒状态与预约资格分别记录，实际购买资格仍由京东确认。

### 时间与提前准备

- **实际开始时间 = 开抢时间 − 提前量**；截止时间为实际开始加持续时间，并受活动结束时间限制。
- 提前量单位为整数毫秒，默认 `0`；持续时间单位为秒，范围 `1–86400`，默认 `60`。
- 实际开始前 20 秒尝试准备结算，目标提前 10 秒就绪；尚未提供价格或禁用勾选时，等待解锁后继续尝试。
- 已准备的结算在提交前快速复核。提前量控制最早提交时刻，不代表能绕过京东开售限制，也不保证毫秒级实际成交。
- 过期场次需手动修改并重新启用，不自动跨日重试。

### 提交方式与核对模式

这两类设置相互独立，均按任务保存。更换方式不会清除历史提交记录。

| 提交方式 | 行为 |
| --- | --- |
| 页面提交（默认） | 使用当前结算页的提交入口。 |
| 调用 API 提交订单 | 使用当前结算页 SDK 生成的新鲜请求，在同一浏览器会话中单次派发。依赖有效结算页，不是脱离网页的接口下单。 |

| 核对模式 | 行为 |
| --- | --- |
| 普通模式（默认） | 核对商品、数量、地址和含运费总额，价格未知或超限时暂停。 |
| 无视价格下单 | 跳过价格上限条件，保留商品、数量和地址核对。 |
| 无需条件核对 | 跳过商品、数量、地址及金额的业务核对；需自行确认当前结算内容。 |

任何模式都保留停止信号、执行窗口、提交防重和订单结果核验。API 结果不明时不会自动改用页面提交；不使用手填 Cookie 或历史签名。详见 [提交方式说明](docs/SUBMISSION_PATHS.md) 与 [提前准备说明](docs/CHECKOUT_PREPARATION.md)。

### 订单结果与人工处理

- 成功需确认付款界面及匹配的新增订单；候选号码或 HTTP 200 本身不表示抢购成功。成功后输出订单号，付款保持手动，超时未付可能被京东取消。
- 提交后结果不明时进入待核验状态，恢复操作只查询订单，不再次提交。不要通过删除或切换提交方式绕过防重。
- 确认未生成订单后，可在任务详情选择“重置到抢购前”；用户确认且程序核验通过后归档旧记录，配置保留并回到停止状态。已有订单或无法核验时不重置。
- 删除仅从工作台移除任务，不取消京东订单；记录保留，可从“已删除任务”恢复。运行中的任务会先停止，已有提交需先核验。
- 登录过期、验证码、配送问题或页面不匹配时暂停，显示原因及可用截图。服务重启后，中断任务标记为待检查，不自动恢复购买。

## 手机连接

电脑和 iPhone 接入同一 Wi-Fi，在工作台打开“手机连接”，扫描二维码或访问显示的局域网地址，输入电脑上的访问码。二维码只包含地址。

手机关闭页面后，电脑继续执行已启用任务。当前不提供手机后台推送；需要及时处理时，保持工作台打开并按需开启声音。

连接失败时检查访客网络隔离及 Windows 专用网络防火墙。可在管理员 PowerShell 中运行 `.\enable-lan.ps1`；脚本仅对核实的助手程序、专用物理网卡、本地子网和指定端口添加规则，不改变网络类型。多网卡可指定 `-InterfaceAlias 'WLAN'`，更换端口或程序后需重新配置。不要将控制台暴露到公网。

## 数据与浏览器

账号会话、数据库、访问码、日志及截图默认保存在 Git 忽略的 `data/`，请将整个运行数据目录视为私人资料。通过 `SHOPPING_DATA_DIR` 指定的其他数据目录也应单独保管，不要上传。发布包仅包含程序、文档和干净浏览器运行文件。

程序使用自带 Chromium 和独立会话，通过本机回环 CDP 接管，不连接个人 Chrome、不复制其 Cookie。调试接口运行期间其他本机程序可能访问该会话，关闭浏览器后接口关闭。

默认跟随系统代理。需要仅助手直连时，先关闭助手浏览器，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File configure-browser.ps1 -Network direct
# 恢复跟随系统代理
powershell -ExecutionPolicy Bypass -File configure-browser.ps1 -Network system
```

设置保存在运行数据目录的 `browser-network.json`，不会修改系统代理。出现页面异常、人工验证、访问频繁或 HTTP 403/429 时，程序暂停自动访问至少 5 分钟并跨重启保留；到期后仍需人工处理、手动恢复。无法承诺免受平台限制。详见 [访问保护说明](docs/ACCESS_PROTECTION.md)。

## 开发与构建

技术栈：Python、FastAPI、异步 Playwright、SQLite，以及 React、TypeScript、Vite。核心负责任务、存储、调度和事件，平台适配器负责商品及购买流程；目前只注册京东。

```powershell
# 测试与前端生产构建
.\test.ps1

# 后端单独运行
.\.venv\Scripts\python.exe -m assistant

# 构建 Windows 发布包（版本目录已存在时会拒绝覆盖）
.\build-release.ps1 -Version '0.2.0'

# 前端开发，后端需另行运行
cd frontend
npm run dev
```

| 路径 | 用途 |
| --- | --- |
| `assistant/` | 后端、调度、存储与平台适配器 |
| `assistant/adapters/jd.py` | 京东页面选择器与流程 |
| `frontend/src/` | 网页控制台 |
| `tests/` | 本地模拟商店与流程回归 |
| `scripts/` | 只读校准、发布审计等维护工具 |
| `docs/` | 接口、验收和版本记录 |

默认端口为 `18765`。源码版可用 `.\start.ps1 -Port 18766`；便携版可先设置 `$env:SHOPPING_PORT=18766` 再启动 EXE。一个数据目录只运行一个服务，不使用多 worker。

## 验证范围与限制

v0.2.0 完整离线回归 282 项通过；前端构建、独立 EXE 启动、编译后 API 选项读写、包校验与私人数据扫描通过。增量测试集合存在重叠，具体记录以 [版本说明](docs/RELEASE-v0.2.0.md) 和 Release 附件 `v0.2.0-validation.json` 为准。

离线模拟、只读结算检查与真实商品下单分别记录。本轮整合未代替用户在京东创建真实订单，不代表所有商品或场次均已验收。API 不保证更快；当前不包含商品 BP 直链适配。验证码、库存、资格、App 限制、页面升级和网络延迟均可能阻止完成购买。首个限定版目标的验收记录见 [验收说明](docs/ACCEPTANCE.md)。
