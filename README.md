# 购物小助手 · 京东优先

**v0.2.0：主分支统一提供页面提交与可选 API 提交。** 创建或修改任务时勾选“调用 API 提交订单”，不再需要单独的 API 分支或另一套程序；默认关闭。保留 v0.1.3 的结算重绘修复、提前准备、“无视价格下单”和“无需条件核对模式”。详见 [v0.2.0 说明](docs/RELEASE-v0.2.0.md) 和 [提交方式说明](docs/SUBMISSION_PATHS.md)。

运行在 Windows 电脑上的本地购物控制台。电脑负责预约、等待开售、浏览器下单与订单核验；同一局域网内的 iPhone 可以查看进度、配置和停止任务。第一版为个人单账号、单件购买，同一账号一次运行一个任务。

**软件测试与真实商品验收分开记录。** 目标为雷鸟 GT Max bilibili 限定版 M 码，SKU `100327520619`。开售后的真实结算及未付款订单验收情况见 [验收记录](docs/ACCEPTANCE.md)。

两种方式共用浏览器登录、预约、购物车、定时、付款界面与订单核验。API 模式使用本次结算页面生成的新鲜请求，不使用手填 Cookie 或旧签名；失败或结果不明时不自动切换另一通道再次下单。历史只读试验与当前边界见 [API 记录](docs/API_TRIAL.md)。

## 开始使用

[正式版本下载](https://github.com/EndermanMY/Shopping_assistant/releases/latest)提供 Windows x64 便携包，内置 Python 运行时和 Chromium，无需安装开发环境。完整解压后双击包内 `start.bat`。升级前停止旧服务；新包不含登录或个人数据，迁移说明见 [v0.2.0 记录](docs/RELEASE-v0.2.0.md)。以下步骤用于源码工作区。

当前工作区已安装项目依赖并构建控制台。双击 `start.bat`，或在 PowerShell 运行：

```powershell
.\start.ps1
```

打开终端显示的本地地址，默认 `http://127.0.0.1:18765`，输入同一终端显示的访问码。启动窗口需保持运行，关闭会停止助手。

首次安装或重新安装时，需要 Python 3.12+、Node.js 22.12+ 或 24+：

```powershell
.\install.ps1
# 如电脑有多个 Python，可以显式指定：
.\install.ps1 -PythonPath 'C:\Path\To\Python312\python.exe'
```

安装脚本使用官方 PyPI/npm 源，Python 安装在项目 `.venv`，Chromium 安装在 `data/browsers`。依赖版本分别由 `requirements.lock.txt`、`frontend/package-lock.json` 锁定。

## 第一个任务

1. 点击“打开京东登录”，在应用专用 Chromium 中完成登录。该目录独立于平时使用的 Chrome；登录会话会保存，账号状态定期刷新。
2. 点击“创建抢购任务”，粘贴京东分享文案、商品链接或 SKU。示例按钮可直接解析目标雷鸟限定版。
3. 核对版本、规格和北京时间场次。“检查网页准备”只读取预约资格、购物车目标行、勾选可用性和订单列表，不会预约、勾选或下单。
4. 填写**最高应付总额（含运费）**与收货地址核对关键字，例如京东默认地址中的街道或小区名。
5. 选择提交方式：默认页面提交；需要 API 时勾选“调用 API 提交订单”。这是每个任务自己的设置，与两项核对模式独立，保存后不会自动启用。保存后点击“启用”，助手检查预约并准备购物车；实际开始前 20 秒尝试准备结算，目标提前 10 秒就绪。尚未解锁的商品在购物车等待，到点继续尝试。已有有效结算时快速复核，按所选方式只提交一次订单。
6. 提交后先确认进入付款界面，再退出本次支付、保留订单并查看订单号。只有付款界面已确认，且新增订单号、商品、数量、金额、待付款状态均匹配，才输出“抢购成功，锁单成功”及订单号。已有订单但付款界面未确认时显示待处理，禁止重复提交。付款由你完成，付款倒计时到期可能取消订单；不表示永久锁库存。成功消息通过实时状态、日志及提示显示，声音开关可启用提示音。

主流程：解析地址 → 检查/办理预约 → 自动加购 → 停留购物车等待 → 到点结算 → 进入付款界面 → 锁单与订单号核验 → 输出抢购成功。若当前商品没有可用加购入口、出现验证码或无法确认付款界面，保留具体原因，暂停人工处理。

预约截止后至开售前，购物车勾选框禁用属于正常状态。助手不会把“勾选不可用”直接判断成已售罄，也不会自动把过期场次移到明天。提前量可填写整数毫秒，默认 0；持续时间可填写 1–86400 秒，默认 60。实际抢购开始 = 开抢时间 − 提前量，截止 = 实际开始 + 持续时间，并受活动结束时间限制。保存时不接受已过去的实际开始时间。源码优化后的未就绪重试间隔：正式开售后前 5 秒为 500 毫秒，随后至第 15 秒为 1 秒，之后为 2 秒；页面请求和加载耗时另计。提前探测失败时对齐正式开售时刻再次检查。

商品信息从电脑商品页读取；表单保留开售时间的秒数。已过期任务显示“修改场次”，需要用户重新解析/确认后保存并启用。是否已预约以当场实际页面检查为准。

## 人工接管与订单保护

- 登录过期、验证码、资格不符、配送问题、页面结构不匹配、价格未知或超限时，任务进入“需要处理”，显示原因及可用的页面截图。
- 有提交记录的任务，恢复操作**只核验订单**。即使点击超时、响应丢失或服务重启，也不会自动再次提交；核对京东订单列表后再决定是否创建新任务。
- 任意任务都可从列表删除；运行中的任务先停止，已有提交则先完成核验。删除保留后台审计记录，可从“已删除任务”恢复；不会取消京东订单。删除结果不明的任务后，同一 SKU 的新购买仍会被拦截，直到恢复原任务并核验。
- 本次未抢购成功且确认京东没有生成订单时，可在任务详情选择“重置到抢购前”。勾选确认后程序检查订单列表，通过才归档旧记录、清除本次待核验状态并回到停止状态；配置保留，过期场次需修改后重新启用。已有订单或无法检查时不会重置。
- 服务重启会保留任务，并将中断的运行任务标记为“待检查”。任务不会自动恢复购买。
- 账号状态首先检测本地浏览器会话，运行任务时会再次读取实际页面，不能只凭 Cookie 存在判断登录有效。
- 普通页面结构变化会要求校准，而不会退回全选购物车或无条件点击按钮。

## 用 iPhone 连接

电脑与 iPhone 接入同一 Wi-Fi，在工作台点击“手机连接”，扫描二维码或打开显示的局域网地址，再输入电脑上的控制台访问码。二维码只包含地址，不包含访问码。

手机关闭页面后，电脑继续执行已启用任务；需要付款或人工处理时，建议保持工作台页面打开并开启声音。第一版不提供手机后台推送。电脑需要保持开机、联网且不休眠。

若无法连接，先确认两台设备不在隔离的访客 Wi-Fi 中；检查 Windows 防火墙是否允许此 Python 服务在**专用网络**被访问。程序不会自动改动防火墙设置，也不会开放公网端口。

需要配置局域网访问时，可在管理员 PowerShell 中运行 `.\enable-lan.ps1`。它核对当前工作区服务后，仅允许现有专用物理网卡、本地子网、助手实际 Python 程序和 TCP 18765，不改变网络类型或默认防火墙策略。多网卡时可显式指定 `-InterfaceAlias 'WLAN'`。更换端口或从源码迁移到 EXE 后，需要针对新端口及实际程序重新配置规则。

京东新版页面可能显示“已设置开抢提醒”。助手会据此等待开售，不再要求不存在的“立即预约”按钮；该状态与“已预约资格”分别显示，实际购买资格仍需在结算时由京东确认。

## 数据与开发

所有账号会话、数据库、截图、访问码、运行日志与浏览器均保存在被 Git 忽略的 `data/`。截图尽可能遮罩地址节点；请将整个目录视为私人数据。应用不会通过 API 返回京东 Cookie 或访问码。

```powershell
# 完整测试与前端构建
.\test.ps1

# 后端单独运行
.\.venv\Scripts\python.exe -m assistant

# 前端开发（后端需另行运行）
cd frontend
npm run dev
```

后端：`assistant/`；前端：`frontend/src/`；场景测试：`tests/`。京东选择器集中在 `assistant/adapters/jd.py`。新平台实现 `Adapter` 协议，并注册到应用工厂，复用核心任务、存储与事件机制。

默认端口 `18765`；源码版可运行 `start.ps1 -Port 18766`；便携版可在 PowerShell 中先设置 `$env:SHOPPING_PORT=18766` 再运行 EXE。启动脚本会先检查端口占用。一个数据目录只运行一个服务实例；不使用多 worker 部署。

维护时可运行 `.\.venv\Scripts\python.exe scripts/verify_live_readonly.py`，通过助手自身 API 只读检查目标 SKU 并保存本地证据。该脚本不会创建、启用或恢复抢购任务。

参考资料与维护日期见 [GitHub 调研](docs/GITHUB_RESEARCH.md)，接口与状态见 [开发接口](docs/API.md)，依赖及参考许可见 [第三方说明](THIRD_PARTY.md)。

## 页面异常与访问保护

继续使用程序内置的独立 Chromium，不连接本机 Chrome、不复制日常浏览器 Cookie。出现“当前页面异常 / 请刷新或切换账号”、人工验证、访问频繁或主页面 HTTP 403/429 时暂停自动访问至少 5 分钟，跨重启保留；期间启用、恢复、商品解析与订单查询不继续访问京东。到期不自动开抢，仍需人工处理并手动恢复；提示再次出现会重新暂停。

购物车短间隔检查主要读取当前页面，整页刷新按 1 秒逐步退避至 5 秒。已提交但结果不明的记录继续保留，遇到限制停止订单重复查询，不重发订单。上述措施不能保证解除平台限制，也不能承诺免封控。


浏览器运行版本由 `browser-runtime.lock.json` 固定，源码安装通过 `install-browser.ps1` 从官方分发下载并校验 SHA-256，不调用本机 Chrome。默认使用应用专用目录和普通启动＋本机 CDP 接管，并跟随系统代理。需要仅助手直连时，关闭助手浏览器后运行 `powershell -ExecutionPolicy Bypass -File configure-browser.ps1 -Network direct`；恢复跟随系统代理用 `-Network system`。设置保存在 `data/browser-network.json`。CDP 仅监听本机回环地址；运行时其他本机程序可能访问该会话，关闭浏览器后接口关闭。

历史本地恢复验证使用 `direct + native_cdp` 和固定专用目录 `jd-native-direct`，用户确认首页、登录后页面及购物车正常。该会话和网络偏好不随发布包提供；新安装需自行登录。只有在用户自己的电脑迁移时才复制所需会话与设置。浏览恢复不替代真实订单验收。
