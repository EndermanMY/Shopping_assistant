# v0.2.0 · 统一提交方式正式版

2026-10-30。主分支统一页面提交和可选 API 提交，独立 API 试验分支退役。保留 v0.1.3 用户已验收的页面路径、语义核对修复和提前结算准备。

## 本次变化

- 创建或修改任务时新增“调用 API 提交订单”，默认关闭、按任务保存；任务列表与详情显示所选方式。
- API 使用当前页面 SDK 当场生成的已校准 XHR 请求，同页原生 fetch 单次派发，回填实际响应；不用手填 Cookie 或历史签名。
- 页面及 API 都支持普通核对、无视价格、无需条件核对。核对逻辑与提交方式独立，旧任务不自动开启 API。
- 保留实际开始前 20 秒准备、目标提前 10 秒就绪、毫秒提前量及秒级持续时间。API 最终派发前再检查停止、执行窗口与持久提交意图。
- SDK 加载中按钮变灰不会在无需条件核对模式中造成错误暂停；CORS 预检与真正订单请求分开处理。
- 请求不受支持时暂停；结果不明时只查订单，不切换方式重复提交。403/429 和人工验证沿用访问保护。

## 使用与迁移

完整解压 Windows x64 ZIP，双击 `start.bat`。默认端口 18765，使用终端显示的访问码。安装包内置 Python 和独立 Chromium；首次使用需自己登录。

升级前停止旧助手，保留旧包以便回退。同一数据目录只运行一个服务。需要保留个人会话时，仅在本人电脑将旧 `data/` 备份后迁移到新包，并保留新包的 `data/browsers/`；不要把个人数据上传 GitHub。源码测试使用 `SHOPPING_DATA_DIR=data-api` 的用户可继续原目录，不会自动合并两份数据库。服务重启不会自动启用任务。

原 `submit_mode` 仅为兼容输出，新开关以 `use_api` 为准。没有显式 `use_api=true` 的旧任务继续页面提交。旧提交意图、候选订单号与订单结果保留，不因换模式而清除。

## 验证与限制

发行验证包括前端构建、完整离线回归、独立 EXE 启动/浏览器空白页冒烟测试、ZIP 清单与哈希校验、私人数据扫描。完整离线回归 282 项通过，随后 API/限流等增量回归 48 项及最终接口保护 7 项通过；这些集合有重叠。离线模拟覆盖两种浏览器启动方式、API 单次派发、按钮加载、条件模式、CORS、断网、停止、未知接口、限流及未知结果恢复。编译产物校验见发行附件 `v0.2.0-validation.json`，详细边界见 [验收记录](ACCEPTANCE.md)。

本次整合未代替用户在京东创建真实订单。历史真实只读 API 试验与用户对 v0.1.3-dev 的确认不能扩大成当前所有商品、API 或 BP 直链的真实验收。API 仍依赖有效结算页和网页 SDK，不保证总耗时更短，也不能保证不触发平台限制。

发行包只含程序、静态界面、文档、许可与干净浏览器文件；不携带账号、Cookie、访问码、任务数据库、地址、订单、截图或运行日志。个人配置需用户本地填写。
