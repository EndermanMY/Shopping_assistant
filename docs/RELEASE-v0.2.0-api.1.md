# v0.2.0-api.1 · API 下单实验版（Windows x64）

分支：`codex/api-trial`。这是可选 API 提交通道的预发布版本；日常使用推荐正式版 [v0.1.2](https://github.com/EndermanMY/shopping-assistant/releases/tag/v0.1.2)。

## 使用

完整解压后双击 `start.bat`，默认地址 `http://127.0.0.1:18766/`。运行数据保存在本包的 `data-api/`，不会读取正式版的登录目录和任务。初次使用在助手自带独立浏览器内重新登录。

创建任务时，“提交方式”默认仍为“页面提交”。需要试验时，明确选择“API 下单（实验）”，设置未来场次、最高总额、地址关键字，再自行启用。只支持单账号、单件与手动扫码支付。无可校准请求或非手动付款方式时暂停。

## 实验通道如何工作

1. 预约、加购、购物车定时等待和结算页校验沿用正式版。
2. 当前结算页自己的 SDK 生成带动态参数的 XHR 下单请求。该请求在发往网络前暂停，不直接提交，也不保存到文件。
3. 重新核对商品、数量、地址、金额、场次和停止信号；确认持久化提交意图后，使用同一助手浏览器的原生 `fetch` 发出一次当前请求。沿用浏览器会话和网络，不手工伪造签名、Cookie 或指纹。
4. 原先暂停的 XHR 用这次真实 API 结果在本地完成，供页面继续显示收银台；它不会再发一份网络请求。页面保留防重拦截，失败后 SDK 重试不能继续提交。
5. API 返回号码先保存为候选，再核验付款界面和具体新订单；信息不足保持待处理，恢复只核验。不会 API 失败后回退 DOM 再下单。

这是依赖当前网页生成参数的 API 试验，**不是完全脱离网页的无头下单，也不保证比页面提交更快**。仅接受已校准的当前页 XHR；网页升级成其他调用方式时先暂停。参数超过 2 秒有效期、跨出场次、价格/页面变化或用户停止时不派发。

403/429、已知平台限制码和人工验证触发全会话暂停。不要通过连续重置、换通道或反复登录重试；不提供免风控承诺。

## 验证与隐私

完整回归 **231 项通过**（400.54 秒，1 条既有依赖弃用警告），覆盖本地模拟商店的成功链路、一次网络派发、原生 CDP、断网后只核验、SDK 重试拦截、价格变化、停止信号、时钟回调、限制访问、不支持的 SDK、子框架请求拒绝和手机端选项保存。测试服务使用安全高端口，测试浏览器默认拦截京东商品/API 真实请求。编译包和隐私检查见随 Release 提供的 validation.json。

真实京东只读结算 API 曾验证通过；**本版没有代替用户执行真实 API 下单，真实未付款订单验收仍待用户测试**。不要把模拟成功当作目标商品抢购成功。

包内不包含账号、Cookie、访问码、任务、地址、个人订单、截图或诊断日志。`data/` 只包含浏览器运行文件，`data-api/` 首次启动后在用户电脑本地生成。不要上传这两个目录里的私人运行资料。
