# 购物小助手 v0.1.1 · Windows x64

Windows x64 便携版本。完整解压后双击 `start.bat`，默认地址 `http://127.0.0.1:18765/`；访问码显示在运行终端。启动窗口需保持打开。

修复任务删除和定时设置。完整解压后运行 `start.bat`；保留 `_internal`、`data/browsers`，无需安装 Python、Node.js 或 Chromium。

## 变化

- 修复新版购物车分列布局的数量定位，按完整 SKU 行读取数量，并等待控件加载。
- 兼容“去结算（1）”与“领券结算（1）”，只允许唯一可见的单件入口，等待异步计数更新。
- 默认端口调整为 18765，避免本机 Windows 对 8765 的保留限制；绑定被拒绝与端口占用分别提示。源码服务和便携服务不能同时使用同一数据目录。

- 主流程改为：解析 → 检查/办理预约 → 自动加购 → 停留购物车等待 → 到点结算 → 进入付款界面 → 锁单并核对订单号 → 输出抢购成功。已有 SKU 不重复加购；数量在购物车核对/调整为 1。
- 最终成功必须同时具备付款界面证据与匹配的新订单号。已创建订单但付款界面未确认时显示待处理，保留订单号，不再提交。成功消息直接输出订单号和金额。
- 付款界面证据随任务持久保存，重启后仅核验，不再次提交。关闭支付弹窗/离开收银台不会点击取消订单或扣款。

- 任务列表和详情均提供删除，成功/失败/等待/运行中的任务都可以删除。运行中先停止；如已有提交，先完成核验。删除仅从工作台移除，不取消京东订单。
- “已删除任务”可恢复到列表，不会自动启用。后台保留核验记录，结果不明的提交不能靠删除任务来绕过重复下单保护。
- 增加“提前抢购时间（毫秒）”，默认 0，可填 0–86400000 的整数。
- “持续抢购时间（秒）”改为自由输入，范围 1–86400，默认 60。
- 实际开始 = 所填开抢时间 − 提前量；截止 = 实际开始 + 持续时间。界面显示北京时间及毫秒后的实际起止时间。例如设 10:00:00、提前 500 毫秒、持续 60 秒，执行区间为 09:59:59.500–10:00:59.500。
- 提前量为 0 时，购买动作不应早于所填时间。预约/登录准备可以提前做；结算及提交前再检查时间。时钟回调时也不会提前提交，持续时长不会被系统时间回调无限延长。
- 保存时拦截过去的实际开始时间。重新解析商品保留已填写的时间；需要采用商品页时间时，点击“使用此时间”。

毫秒用于配置提前量，实际点击时间仍受 Windows 调度、页面加载和网络影响。无库存、验证码或页面改版不承诺抢购成功。

## 更新

不要同时运行两份服务。若需要从旧版迁移，先停止旧版正在运行的任务并关闭服务，备份旧版 `data/`，再将其中 `assistant.db`、`access.json`、`browser/` 和所需截图复制到新版 `data/`；保留新版 `data/browsers`。数据库首次启动自动升级，旧任务提前量为 0。启动后检查配置并重新启用需要执行的任务。

发布 ZIP 不含用户账号、任务、地址或访问码。已有源码工作区的数据保留原位，无需迁移。
