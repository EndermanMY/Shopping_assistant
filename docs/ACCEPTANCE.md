## 预约、购物车等待与付款锁单流程修正

后续实页报错修正：用户截图显示实际按钮为“领券结算（1）”，旧逻辑仅匹配“去结算”，导致到点后报“未找到唯一的单件结算入口”。当前识别两种文案、半角/全角括号，只取可见且数量为 1 的入口；勾选后的计数刷新最多等待 5 秒，并受场次截止时间限制。后续发布前补充本地浏览器回归；真实点击结算、抢购验收由用户操作。用户反馈现阶段整体已可运行，目标限定版开售验收仍单独记录。

当前源码链路：解析 → 检查/办理预约 → 自动加购 → 停留购物车等待 → 按实际开始时间结算 → 提交一次 → 确认进入付款界面 → 退出支付保留订单 → 核对订单号 → 输出抢购成功。已在购物车的 SKU 不重复加购，数量核对/调整为 1；真实页面没有可用加购入口时暂停提示，不能绕过页面限制。

付款界面证据与订单号分别核验。仅创建订单、仅看到付款界面、或两处订单号不一致，均不能成为新任务的最终成功结果。进入付款界面的时间持久保存，重启恢复只核验、不再次提交。成功提示包含订单号与应付金额。

2026-10-25 21:14:45 真实只读检查：目标 `100327520619` 的 `reminder_set=true`、`reserved=false`、`cart_found=true`、`checkbox_found=true`、`cart_selectable=false`、`order_list_readable=true`。证据 `data/qa/workflow-live-readonly.json`。当前原限定版任务保持已停止，未自动恢复购买；没有为本轮修正重复生成真实订单，真实开售下单仍待验收。

v0.1.1 同时完成删除及定时修复：运行/成功任务可删除并恢复；后台保留提交及核验记录。新增整数毫秒提前量与整数秒持续时间，显示实际起止边界；拒绝过去的实际开始时间，解析商品不覆盖手填时间。计时测试覆盖时钟回调及默认不提前进入结算，界面覆盖 1440/375 像素的创建、删除和恢复。升级前已备份本机数据库，未使用真实商品重复下单。

历史预约问题修复后曾进入等待开售；任务随后由用户停止。真实任务配置、提交状态及证据仅保存在本机，不随公开源码发布。

1. 在应用浏览器核对默认收货地址及限定版 M码，确认目标在购物车。

4. 电脑保持开机、联网及运行。开售后验证目标勾选解锁、仅目标 SKU 结算、总额不超上限、地址及数量正确。
5. 实际出现可核对的新增未付款订单号后，才将本项改为通过；由用户手动付款。
6. 如要求 App 下单、出现验证、页面结构变化或订单无法明确核验，保留具体原因与本地截图，记录阻塞，不用其他商品替代验收。

## 已知边界

- 第一版只有京东适配器、个人单账号、单件购买及电脑网页执行端。
- 自动化能力不承诺库存命中或下单成功；当前也未证明目标商品开售后可完成电脑网页提交。
- 第一版没有 iOS 执行端、Android 执行端、云端任务、手机后台推送、自动付款及跨日自动重试。
- 等待场次使用电脑北京时间和单调时钟倒计时，未实现外部授时；电脑系统时间应保持正确，不宣称毫秒级校时。
