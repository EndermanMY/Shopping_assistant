# v0.1.3-dev · 主分支页面提交

回到 `main` 的页面点击方案，不提供直调 API 开关。兼容旧 API 任务配置为 `dom`，原登录资料、任务、提交意图和订单号不清空。本轮仅更新源码运行版，不编译或发布便携包。

## 结算核对修复

旧方案比较完整 DOM HTML、节点、样式和各区域 React 事件函数，焦点变化及重新渲染也会使核验失效。现只比较商品链接/标题、数量、选中地址、实际金额和付款选择，忽略追踪参数、样式、高亮及无关回调。商品详情的核验动作完成后才保存可复用证据，避免核验自己的渲染动作使证据立即失效。

复用证据时仍检查 SKU 导航回调变化。真实业务值在核对过程中改变时最多核对两次，仍变化则暂停并提示变化区域，不继续十余次循环。保留提前 20 秒开始准备、目标提前 10 秒完成、实际时刻等于用户时间减毫秒提前量的调度。

## 可选模式

“无视价格下单”仅跳过金额和上限检查。“无需条件核对模式”跳过预约资格、商品、数量、地址和金额核对，预算及地址输入禁用；按购物车和结算页现状下单，可能数量、商品或收货地址不符合原本预期。两者默认关闭，必须由用户在任务中选择保存。

无需条件核对模式保留执行时刻、截止时间、停止、提交意图持久化、只提交一次及手动付款；登录失效、验证码、403/429 仍暂停，禁用勾选仍须平台解锁。不尝试解除京东平台限制，也不使用个人 Chrome。

成功只取本次提交响应或付款页的订单号及付款页证据，明确标注购买条件未核对；没有订单号则结果不明，不能据此自动重试。商品和金额不会伪装成已经核实。

## 本地使用

源码默认 `start.bat` 使用 8765。当前工作台可显式以 18766 启动，并通过 `SHOPPING_DATA_DIR` 沿用本机原数据目录；不要同时运行两个服务访问同一个目录。所有数据目录、登录、访问码、任务和截图都排除在版本控制之外。

本轮只用离线模拟与本地控制台测试；真实抢购由用户复测，不自动启用现有任务。
