# 独立浏览器访问异常处理（2026-10-27）

## 已确认的现象与边界

用户报告日常浏览器访问正常，而应用专用浏览器显示“当前页面异常 / 请刷新或切换账号”。这不能单凭截图归因为某个浏览器检测规则。按用户要求仍使用程序内置独立 Chromium；未连接本机 Chrome，未复制其 Cookie，未修改浏览器指纹或自动处理验证码。

本轮备份了任务数据库，并将已关闭的旧应用会话目录移至 `data/browser/jd-backup-20261027-034205`，随后建立新的 `data/browser/jd`。用户重新登录后确认异常仍存在，因此本轮会话重建没有解决访问异常，不能宣布京东适配恢复。原任务及提交记录保留，未启用、恢复、重置或提交真实任务。运行状态证据为 `data/qa/access-protection-live.json`。

## 本轮保护

- 识别页面异常、访问频繁、人工验证、风险拦截路径，以及京东主页面导航的 HTTP 403/429。
- 同一应用会话进入 5 分钟冷却，记录保存在忽略的 `data/jd-access-pause.json`，重启不会清空。反复点击启用/恢复不会延长冷却，也不会访问京东。
- 冷却结束不会自动启用任务。页面仍异常时再次检测并暂停，需要人工处理后手动操作。
- 保留快速本地 DOM 检查，整页刷新从 1 秒逐步退避到最多 5 秒，不再每次轮询都刷新。
- 订单页遇到访问限制或必须人工处理时停止重复查询；已提交但无法核验的记录保留为结果不明，不重复提交。
- 登录后的当前京东页面也做本地 DOM 检查，避免 Cookie 存在却将错误页面显示为正常。该检查不发送网络请求。
- 暂停期间打开登录操作只显示应用浏览器当前窗口，不反复请求登录。

前端生产构建通过。访问保护、刷新退避、订单流程的完整回归为 **134 passed, 1 warning**，208.02 秒。之后加入登录后本地页面状态检测，保护及 API 定向回归为 **28 passed, 1 warning**，2.41 秒。日志为 `data/access-protection-regression.log`、`data/access-protection-final-focused.log`。测试使用隔离模拟数据；唯一警告为既有 Starlette/HTTPX 弃用提示。

- 内置 Chromium 156.0.8078.4 普通启动、沿用旧会话时仍异常。
