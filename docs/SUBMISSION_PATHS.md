# 页面提交、API 提交及结算直链

核对时间：2026-10-30，适用于主分支 v0.2.0。独立 API 试验代码已统一到主分支，保留主分支最新语义核对与条件模式。

| 项目 | 页面提交（默认） | 勾选“调用 API 提交订单” |
| --- | --- | --- |
| 配置 | `use_api=false` | `use_api=true`，按任务保存 |
| 实际提交 | 点击按钮，由网页发送请求 | SDK 生成本次 XHR，联网前拦住，再用同页原生 fetch 发送一次，回填真实响应 |
| 浏览器、购物车、结算页 | 都需要 | 都需要，并非脱离页面的独立客户端 |
| 提前结算准备、毫秒提前量 | 有 | 有 |
| 无视价格 | 可选，默认关闭 | 可选，默认关闭 |
| 无需条件核对模式 | 可选，默认关闭 | 可选，默认关闭 |
| 最新结算重绘修复 | 有 | 有 |
| 停止、单次提交、未知结果核验 | 保留 | 保留；不会回退另一通道重试 |
| 未校准请求 | 页面流程及结构检测 | API 请求联网前暂停，不猜参数或重放旧请求 |

默认不开启 API。旧主分支任务不改变提交方式；旧试验数据只有 `submit_mode=api` 时也需重新显式选择 `use_api`。不复制旧试验目录到新包，不通过切换方式清除提交记录。

API 仍有点击、签名生成、拦截和复核成本，不能保证比已预热页面更快。接口 403/429、验证码或页面异常触发现有暂停机制，不通过增加并发、伪造指纹、复用失效签名或轮换账号绕过限制。

## 时间与订单

实际开始 = 开抢时间 − 用户提前量；提前 20 秒尝试准备，目标提前 10 秒完成结算核对。到点快速复核已准备页面，按所选方式提交。样式、跟踪参数和无关 React 重绘不触发完整重查；真实商品、数量、选中地址、付款方式或受限金额改变才使证据失效。连续变化时最多重读两次后暂停。

开售前勾选禁用或无有效结算时仍需等京东解锁。“无视价格”只放开金额条件，不能让平台接受尚未开售的商品。“无需条件核对”也不能解除网站按钮或服务器限制。

两种方式都先持久化本次提交意图。API 原始请求体、EID 等只保留内存，不写日志、数据库或发行包。SDK 自动重试被阻止；超时、断网或未知结果只核验订单，不自动换通道再下单。后续任务使用新任务页，旧页防重仍保留。

正常模式要求本次订单号、商品、数量、金额及待付款证据，并确认付款界面；无需条件核对模式只用本次响应/付款页的具体订单号，不假定 SKU、数量和金额已核对，结果明确标注。付款仍手动完成，不执行扣款。

## 结算直链

普通购物车结算 URL、带商品/活动/会话参数的直接购买 URL、订单生成后的付款 URL 不等价。历史项目中的 `getOrderInfo.action` 只能作为流程参考，不能据此认定是当前目标 SKU 的有效入口。主分支尚未实现商品级结算直链适配。

由当前会话及目标商品实际产生并验证有效的直购入口，可能省掉购物车勾选、合计刷新和一次跳转；这是待验证的推断，不是已完成的优化。它仍可能需要登录、预约资格、活动参数、结算令牌及动态签名，也不能据此断言开售前可以下单。

已提前停留在结算页时，直链主要缩短准备阶段，对到点后的路径未必继续提速。开售前被锁在购物车时，有效商品直购入口更值得研究，需验证是否进入正确结算状态，不能只看 HTTP 200。付款链接需要已有订单号，不是创建订单的入口。
