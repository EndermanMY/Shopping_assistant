# 当前页面下单、API 分支及结算直链

核对时间：2026-10-30。基于本地 `main` 与 `codex/api-trial` 代码，分支修改后需重新核对。

| 项目 | main / v0.1.3 | codex/api-trial / 0.2.0-api.3 |
| --- | --- | --- |
| 提交方式 | 页面点击，由京东网页发送请求 | 默认仍是页面点击，可选择实验 API |
| API 实现 | 只观察页面本次响应，不重放 | 点击取得网页签名 XHR，在发送前拦住，经复核再以同页原生 fetch 单次派发，回填真实响应 |
| 浏览器、购物车、结算页 | 都需要 | 都需要，并非脱离页面的独立客户端 |
| 提前结算准备、毫秒提前量 | 有 | 有 |
| 无视价格 | 可选，默认关闭 | 可选，默认关闭 |
| 无需条件核对模式 | 可选，默认关闭 | 当前没有 |
| 最新结算重绘修复 | 有 | 尚未同步，仍采用旧 DOM 证据 |
| 验收 | 用户确认开发版通过，随后定版 | 不能沿用主分支验收结论，也不能据此认定更快 |

API 分支的点击、签名生成、拦截和复核都在 fetch 前执行。当前实现没有省掉这些阶段，不能仅凭“API”推断更快。继续比较前应先同步主分支修复，再以同一商品、条件模式、会话和网络分段测量准备、派发、响应和订单号。

## 结算直链

普通购物车结算 URL、带商品/活动/会话参数的直接购买 URL、订单生成后的付款 URL 不等价。历史项目中的 `getOrderInfo.action` 只能作为流程参考，不能据此认定是当前目标 SKU 的有效入口。主分支尚未实现商品级结算直链适配。

由当前会话及目标商品实际产生并验证有效的直购入口，可能省掉购物车勾选、合计刷新和一次跳转；这是待验证的推断，不是已完成的优化。它仍可能需要登录、预约资格、活动参数、结算令牌及动态签名，也不能据此断言开售前可以下单。

已提前停留在结算页时，直链主要缩短准备阶段，对到点后的路径未必继续提速。开售前被锁在购物车时，有效商品直购入口更值得研究，需验证是否进入正确结算状态，不能只看 HTTP 200。付款链接需要已有订单号，不是创建订单的入口。
