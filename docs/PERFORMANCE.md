# 抢购速度优化（2026-10-26）

状态：源码修改；真实验收由用户操作。不修改已发布 v0.1.1 的 ZIP 或标签。

用户提供的日志显示：09:59:59 进入运行，10:00:03 开始提交，10:00:18 付款界面未确认，10:00:24 新订单未确认。后两段属于提交后的取证与核验，不能把全部 25 秒当作提交延迟，也不能把“提交动作”当作订单创建成功。

## 本轮修改

- 新版结算页通过商品详情实际跳转 URL 核对 SKU。初次结算与提交前均保留独立核验，但只等待导航提交（commit），不等待详情文档及阻塞脚本完成。错误 SKU、非京东目标及无明确跳转仍拒绝提交。
- 一次读取购物车中已选 SKU 的候选集合，去除重复的图片/标题链接。对每个需要取消的商品仍重新定位并检查真实勾选框，再执行操作；结算清单仍必须只有目标 SKU。
- 未就绪时，正式开售后前 5 秒的等待为 500 毫秒，5–15 秒为 1 秒，之后为 2 秒；实际循环还包含页面加载耗时。提前量触发的探测未解锁时，下一次检查尽量对齐正式开售时刻。继续受任务截止、活动截止、停止信号及系统时钟检查限制。
- 使用单调时钟记录当次结算检查耗时，以及包含提交前复核的提交动作耗时，放入现有日志消息，不增加关键路径的额外数据库写入。

## 保留的保护

最后一次核对精确 SKU、数量、地址、总额及手动扫码付款方式；先持久化提交意图再点击一次。任何提交结果不明仍只核验订单，禁止为了速度重复提交。付款界面与新订单证据不足仍保持待处理；未缩短取证窗口或提前报告成功。

## 验证

使用本地模拟店测试。新增场景故意让商品详情的阻塞脚本无法完成，要求初次与再次 SKU 核对都能在脚本放行前返回；同时验证提前探测对齐及重试节奏。沿用错误 SKU、超预算、错误地址、数量不符、验证码、窗口结束、停止与未知提交结果的保护回归。

本轮没有启用、恢复或提交任何真实京东任务；不承诺固定抢购耗时或订单成功率。运行旧 EXE 不会自动加载源码修改。

完整回归结果：**112 passed, 1 warning**，193.93 秒；日志 `data/speed-final-tests.log`。唯一警告为既有 Starlette 测试客户端 HTTPX 弃用提示。聚焦新版结算和慢脚本核验的 6 项测试通过（9.93 秒）。

## 2026-10-27 访问保护调整

保留快速读取当前 DOM，整页刷新另设 1–5 秒退避，不再每次轮询都发起导航。识别页面异常、访问频繁、人工验证及主导航 403/429 后，全会话持久暂停 5 分钟。停止自动重试订单列表；登录后的页面异常也会通过本地 DOM 状态检查显示。冷却到期仍需手动操作，不会自动购买。

## 2026-10-29 API 试验

已为提交接入同会话 API 响应取证、候选订单号持久化和接口风控保护。明确拒单时跳过付款页空等；不增加下单请求数量。API 直调原型在本地浏览器模拟 API 中验证一次派发及超时防重；真实京东只读结算 API 直调通过，真实 API 下单尚未验证。证据、边界和待办见 [API_TRIAL.md](API_TRIAL.md)。
